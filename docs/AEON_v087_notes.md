## 2. ゲームのコンセプト

- **Unityを使わずブラウザで動く2D横スクロール探索アクションのプロトタイプ**。
- 舞台は高級ホテルの上質感と静かなSF空間を掛け合わせたオリジナルの「PRIVATE SUITE」。『DEATH STRANDING』等は**ムードの参考**であり、固有のデザイン・素材・ロゴ等をそのままコピーしない。
- 白/銀/グレーの曲面内装、青い間接照明、暖色アクセント、反射床、ラウンジ、休息ポッド、窓、コンソール、区画ゲートなど。豪華だがノイズ過多にはしない。
- キャラは**成人女性のオリジナル黒髪ロング・長身感・曲線的な体格・光沢ある銀白の未来スーツ**。どの動作でも顔・髪・体型・スーツのデザインと描線を揃える。
- 実装はCanvasベース、ゲームエンジンなしのHTML/JavaScript。単一HTMLに画像を埋め込んだビルドをユーザーに提供する。
- ミッション: 4か所の設備を調べる→ゲート解錠→次区画→探索完了。ミニマップ、HUD、端末ダイアログ、昼夜/照明切替あり。

## 3. ユーザーが承認した現行アニメーションと演出

### 待機
- 足の接地位置が固定され、上下ガタつきがないこと。
- 待機中に大きく脚や腕を動かさない。

### 歩行
- **v0.8.1系の落ち着いた歩行**が基準。肩・腕の振りは小さく、後ろから前への戻りが瞬間的にならないようキー/タイミングを整える。
- 左右脚の交互運動、接地・重心移動を重視。脚が同じ方向へ出て戻る「パカ感」、フットスライド、接地時の跳ねを避ける。
- 差し込み中間コマや腰・肩のわずかな捻りは有効な改善候補だが、**形状が変わった別キャラに見える副作用**に注意。

### 走行・ダッシュ
- ユーザーは「速い歩き」より『ロックマンX』のダッシュに近い、**前傾・短い切り返し・脚を伸ばしたキーポーズを長く見せる**表現を好む（構図/リズムの参考であり素材コピー禁止）。
- ループ端の引っ掛かりを強く嫌う。伸びた姿勢を止めると静止に見えるため、**髪/衣装/上半身の微細な二次動作**で動感を補う。
- ただの逆再生ループをしない。実際にゲーム内で連続再生し、ループ境界と接地、左右脚の交互性を検証する。
- キーポーズの表示時間調整だけでも改善効果が大きかった。枚数を増やす前に**フレーム順・保持時間・ポーズの意味**を確認する。

### ジャンプ
- 既存のジャンプ動作はユーザー評価で概ね良好。高さ/挙動と空中の残像を維持。

### 青い残像VFX
- ダッシュとジャンプの両方に青/シアンの半透明・加算合成風のスプライト残像を適用。キャラの輪郭は鮮明に保ち、色付きフリンジを過度に増幅させない。
- **STANDARDがユーザー承認済みの基準**。ダッシュ時の `TRAIL_LEVELS` 標準値: 最大5枚、alpha 0.36、spawn interval 0.062秒、life 0.43秒、glow 13（コードの単位）。ジャンプはやや控えめ（枚数と生存時間を少し減らす）。
- Gキーで OFF / SOFT / STANDARD / BRIGHT を切替。デフォルトは STANDARD。
- コマのアニメーションを変えず、過去のキャラ状態をワールド座標で保持し、時間とともに消す方式が有効。

### インタラクト
- **v0.8.7のインタラクトポーズがユーザー承認済み**。
- 機材・据置ディスプレイをキャラ画像に含めない。**空中の青いホログラムだけを触る**。
- 手前の腕は身体の横に下ろし、**奥の肩→二の腕→肘→前腕→指先**が自然につながる奥側の腕でタッチする。
- 操作中は**伸ばした腕を出しっぱなし**にする。腕を上げ下げするコマをループさせない。ホログラムのリング/発光だけ微細に脈動させる。
- 待機からの切り替えで足元が移動・ガタつきしないこと。元のキャラクターと絵柄が若干違ってもゲーム中の見え方としてユーザーが許容したv0.8.7を維持。

## 4. 操作・実装の前提

- **PC：** A/D または左右矢印: 移動。Shift+移動: ダッシュ。Space: ジャンプ。E/Enter: 調べる/ダイアログ進行。Esc: ポーズ。G: 残像強度。
- **スマホ横画面（v0.8.8以降必須）：** 左アナログスティックで移動、右DASH長押し、JUMP・USEタップ、ポーズボタン。複数指で同時操作できること。
- F2で旧スプライト/現行スプライト/実験リグが切り替わる実装が残っている場合があるが、**RIGは開発保留**。安定版の通常プレイはスプライトモード。
- v0.8.7 コード上の `GAME_SPEED=1.5`（以前のプロトタイプに比べ操作テンポを約1.5倍にした設定）。理由なく戻さない。
- イメージスプライトの基準: `229×229`セル・6列のアトラス、表示scale 1.3、footY=224 など。**改修時には現行コードの値を実際に再検証**する。
- 単体HTMLに内蔵した画像を使う形が一番手軽。サンドボックスHTMLリンクを押してもUIによってはコード表示になることがあるので、**まずクリック一発で確認できるHTMLリンクを添え、ZIPは補助**。ユーザーは簡略イラストのチャット内擬似ゲームではなく、フル素材の実ゲームを望む。

## 5. 制作・品質検証の重要知見

1. **アニメーションはフレームの枚数だけでは決まらない**。contact / down / passing / up、体重、接地、リズム、ホールド長の整合が重要。
2. **同じ脚を前後させる逆再生の往復は避ける**。左右交互の1サイクルを描けているかチェック。
3. **ループ境界を必ずチェック**。最終コマ→最初のコマの姿勢・足先・髪・重心が破綻していないこと。
4. **足の固定位置と基準線が重要**。待機/歩行/ダッシュ/ジャンプ/インタラクト間でキャラの脚長・立ち位置が飛ばないこと。
5. **高品質なデザイン画とゲームで使えるアセットは別**。1枚の設定資料を無造作に切り出すと輪郭フリンジや縮尺・設置位置のバラつきが出る。再生に使うコマは同一セル寸法・同一画角・透過・アルファ処理が必須。
6. **青/マゼンタ等の透明化残渣は加算VFXで増幅する**。輪郭の半透明画素、色にじみ、背景残りをクリーニングする。
7. **AI画像再生成で同じキャラを保持するのは難しい**。顔・髪・体格・衣装・光沢を厳密に比較。ユーザーに許容されている絵柄と動作は安易に全面差し替えしない。
8. **2Dリグは理論上有効でも、腰・膝を曲げたままのヒゲダンス感や脚長変化が出やすい**。現行では一時中断。後日再開するなら骨長固定、足IK、上半身とのつながり、素材の質感一致を独立検証する。
9. **別AI比較向け設計**。仕様書・操作・評価軸を共通化し、AIごとに独立ブランチで制作・検証する。推奨評価軸は見た目、アニメーション、操作感、VFX、負荷/FPS、コード保守性、修正対応力。
10. **テスト時は実際のブラウザで操作**。構文チェックだけで「動作確認済み」と言わない。待機、歩行、走行、ジャンプ、インタラクト、ゲート解錠、残像、F2/G、移行境界、エラーの有無まで確認してから納品。ブラウザ実行環境がない場合はその旨を明示。
11. **ユーザーが合格とした見た目/動きを尊重**。VFXを足すだけの依頼なら移動速度やアニメフレームに触れない。インタラクト差し替えなら他モーションの素材や機能を保持する。
12. **制作は差分型**。ファイル名は新バージョン、必要に応じてGitブランチと変更履歴を用意する。安定版を消さない。

## 6. これまでの版と判断の履歴

- v0.1: デススト風ムードの主観視点3D空間。UIは比較的好評だが3Dの質感が物足りず、2Dへ方向転換。

- v0.3〜v0.4: スプライト切出し/足元ガタつき/青フリンジ/歩行ループを改善。

- v0.6〜v0.7.1: 2Dボーン/IK試作。手足の動きは理解しやすいが、膝曲がり・脚長/質感・ヒゲダンス感が残る。v0.7にはフレーム指定/関数欠落の不具合がありホットフィックス対応。
- v0.8: 抑制した歩行/ダッシュスプライトと2Dリグ併用。
- **v0.8.1**: 歩行/ダッシュのキーポーズ保持時間を調整。ユーザー評価で動きが大幅改善。以降のモーション基準。
