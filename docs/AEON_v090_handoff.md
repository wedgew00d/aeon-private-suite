## 1. v0.8.8 で出ていた問題（v0.9.0 を作った理由）

ユーザーの指摘は「操作が不便」「スマホで、無理に画面へ収めていて小さく見づらい」「操作ボタンが画面の外にあって素人っぽい」。確認できた原因は次のとおり。

- canvas を 16:9 固定で収めていた。横長のスマホでは左右に黒帯が出て、絵は画面幅の約7割だった。
- スティックとボタンを画面の四隅に置いていたので、黒帯の上に乗っていた。
- canvas に描くマーカー名が canvas と一緒に縮み、スマホで約6pxだった。HUD の文字も 8〜9px まで縮めていた。
- PC では枠の幅が固定で、高さの低いウィンドウでは下がはみ出していた。

## 2. 置き換えた方針

| 項目 | v0.8.8 まで | v0.9.0 から |
|---|---|---|
| 画面の比率 | 16:9 固定。余りは黒帯 | canvas は常に画面全体。ワールドの縦を基準に、横に見える範囲が変わる。黒帯は出さない |
| 低い画面 | 全体を縮める | ワールドの縦 720 のうち 600 だけを映す（キャラクターが約1.2倍） |
| 縦持ち | 「横向きにしてください」で止める | 上にゲーム、下にパネルと操作を置いて、そのまま遊べる |
| 文字 | 画面に合わせて縮める | CSS ピクセルで固定。狭い画面では飾りの行を消す |
| ダッシュ | DASH ボタンを押し続ける | スティックを大きく倒す（DASH ボタンは廃止） |
| スティック | 左下に固定 | 画面の左半分の、触れた場所に出る。台座が指を追う |
| 調べる | USE ボタン | USE、対象の上の札をタップ、マーカーをタップ（自動で歩いて調べる） |
| パネル | 閉じるボタン | どこかをタップ、または移動の入力で閉じる |
| ファイル | 単一HTMLを16分割した `parts/` を実行時に結合し、文字列置換でパッチ | 普通の構成（`index.html`、`css/`、`js/`、`assets/`）。`parts/` とローダーは廃止 |

変えていない方針: モバイル対応は必須、移動＋ジャンプの同時タッチ、ノッチなどの安全領域を避ける、誤スクロールと拡大の抑止、PC のキーボード操作、リリースごとの PC とモバイルの確認。

## 3. 変えていないコード

移動速度（`GAME_SPEED`、172 / 315）、ジャンプ、`getFrame()` のコマ順と保持時間、`TRAIL_LEVELS` と残像の描画、リグの実験コード、ステーションの定義と進行。`js/game.js` のこれらは、v0.8.7 のスクリプトから文字単位で同じ。`assets/` の画像は、v0.8.7 の単一HTMLに埋めこまれていた base64 をそのまま復号したファイル（再圧縮していない）。`lounge` は `suite` と同一の画像だったので、1枚を共用している。

## 4. コードの読み方（`js/game.js`）

前半が v0.8.7 由来のゲーム本体、後半（`Layout` の見出し以降）が画面の割り付けとポインタ入力。

- **ワールド座標は従来どおり**（縦 `H=720`、床 `FLOOR=600`、全長 `WORLD=3200`）。描画は今もワールド単位で書く。
- 固定の `W=1280` は無い。**見えている幅は `VW`**（可変）。画面端の判定やカメラには `VW` を使う。見えている縦は `VY`（上端）から `VH`。
- `layout()` が、ウィンドウの大きさから `VW / VH / VY`、canvas の実解像度、`K`（ワールド→canvas の倍率）、`cssScale`（ワールド→CSSピクセル）、`uiF`（マーカーの拡大率）を決める。`render()` の先頭で `ctx.setTransform(K,0,0,K,0,-VY*K)` を掛ける。
- 入力は `inputAxis()`（スティックがあれば優先、無ければキー）と `running`（ダッシュ中か）に集約した。`keys.run` を直接読まない。
- `autoTarget` は、マーカーをタップしたあとの歩き先。手動の入力で解除される。
- 縦長のウィンドウでは `.frame` に `band-mode` クラスが付き、CSS が配置を切り替える。タッチ端末では `body.touch`。
- HUD のミニマップは canvas ではなく DOM（`#minimap`）。

## 5. 今後の変更で守ること

- 新しい UI の文字は CSS ピクセルで決め、スマホで 11px を下回らせない。canvas に描く文字は `uiF` を掛ける。
- 操作ボタンはゲーム画面の上に重ねる。画面の外（余白や帯）に置く設計に戻さない。
- 新しい操作には、キーボードとタッチの両方の入口を用意する。タッチは `pointerdown` で受け、`button` 要素の上ではスティックを始めない（`frame` の `pointerdown` を参照）。
- 同じタップが、開いた直後のパネルを閉じてしまうことがある（v0.9.0 の確認中に発生）。パネル側のクリックは、開いてから 0.25 秒は無視している。新しいパネルでも同じ対処を入れる。
- 画像は `assets/` にファイルで足す。HTML や JS に base64 で埋めこまない。分割ファイルにも戻さない。大きいファイルを GitHub 連携で送れない場合は、分割せずにユーザーへ伝える。
- 単一HTMLのスタンドアロン版は、v0.9.0 では作っていない。必要になったら、`main` の内容から別途作る（`main` の構成は変えない）。

- 仮の値: スティックの歩きとダッシュの境目（指の移動で約28px）。実機の感触で調整する前提。
